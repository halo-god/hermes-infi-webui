# 沙箱部署指南（Agent 子进程隔离）

> 生产红线：agent 子进程会执行代码 / 读写文件 / 联网，是系统最大攻击面。
> 本指南给出适配 Hermes 项目的 bubblewrap / firejail 完整配置。
> 实现见 `backend/agent_runner/sandbox.py`；rlimits 层配置见[运维文档](运维文档.md) §4。

---

## 0. Agent 运行时的依赖清单（绑定依据）

| 路径 | 用途 | 沙箱内权限 |
|---|---|---|
| `{HERMES_BIN}`（如 `/usr/local/bin/hermes`） | agent 启动命令 | ro（含其安装树） |
| `{HERMES_HOME}`（如 `/srv/hermes/.hermes`） | config.yaml / profiles / sessions / skills / cache / auth.json | **rw**（agent 会写会话、缓存、记忆） |
| hermes CLI 安装树 + venv | Python 解释器与依赖 | ro |
| `{cwd}`（= `WORKSPACE_ROOT/{conversation_id}`） | 会话工作目录（工具产出物） | **rw** |
| `/tmp` | 临时文件 | rw |
| `/dev`、`/proc` | python / psutil / 随机数 | bwrap `--dev`/`--proc` 最小挂载 |
| `/etc/ssl`、`/etc/resolv.conf`、`/etc/hosts` | TLS 证书与 DNS | ro |
| LLM / MCP 网络出口 | 模型 API、外部 MCP 服务器 | 见下方网络方案 |

> 路径随部署而定：裸机默认 `HERMES_HOME=~/.hermes`、`WORKSPACE_ROOT=~/hermes-data/workspaces`；
> Docker 见 `docker/compose.yaml` 的 volume 挂载。以下示例用 `{HERMES_HOME}`、`{HERMES_AGENT}` 占位。

---

## 1. 方案 A：bubblewrap 断网 + 宿主 HTTP 代理白名单（推荐）

agent 与 LLM/MCP 的流量统一走宿主 HTTP(S) 代理，代理侧做出口白名单；
bwrap 内 `--unshare-net` 彻底隔离网络命名空间。

**SANDBOX_CMD（一行，经 `shlex.split` 解析，`{cwd}` 会被替换为会话目录）：**

```bash
bwrap --die-with-parent \
  --unshare-pid --unshare-uts --unshare-ipc --unshare-net \
  --ro-bind /usr /usr \
  --ro-bind /lib /lib \
  --ro-bind /lib64 /lib64 \
  --ro-bind /bin /bin \
  --ro-bind /etc/ssl /etc/ssl \
  --ro-bind /etc/resolv.conf /etc/resolv.conf \
  --ro-bind /etc/hosts /etc/hosts \
  --ro-bind {HERMES_AGENT} {HERMES_AGENT} \
  --bind {HERMES_HOME} {HERMES_HOME} \
  --bind {cwd} {cwd} \
  --bind /tmp /tmp \
  --dev /dev \
  --proc /proc
```

**配套（agent-runner 进程环境）：**

```bash
export SANDBOX_ENABLED=true
export SANDBOX_CMD="bwrap ...（上面整段）"
# 沙箱内全部出网流量经代理（OpenAI SDK / aiohttp / httpx 均遵循标准代理变量）
export HTTPS_PROXY=http://proxy.internal:3128
export HTTP_PROXY=http://proxy.internal:3128
export NO_PROXY=localhost,127.0.0.1,minio.internal
```

**代理侧白名单（示例，按实际模型/MCP 调整）：**

```text
api.deepseek.com / api.openai.com / openrouter.ai / inference-api.nousresearch.com
mcp.jin10.com 等外部 MCP 域名
```

> 若个别 agent 工具需直连（如生图服务），在代理白名单追加对应域名即可，
> 无需改动沙箱命令 —— 隔离与放行解耦。

## 2. 方案 B：firejail + netfilter 出口白名单（无代理环境）

firejail 支持按目标 IP/端口做出口过滤，适合无法架设代理的场景。

```bash
export SANDBOX_CMD="firejail --net=eth0 \
  --private-dev \
  --caps.drop=all \
  --timeout=600 \
  --netfilter=/etc/hermes/agent-netfilter.rules"
```

**`/etc/hermes/agent-netfilter.rules`（只放行 LLM + 必要出口）：**

```text
*filter
:INPUT DROP [0:0]
:FORWARD DROP [0:0]
:OUTPUT ACCEPT [0:0]
-A OUTPUT -o lo -j ACCEPT
-A OUTPUT -p udp --dport 53 -j ACCEPT          # DNS
-A OUTPUT -p tcp -d 198.18.0.1 --dport 3128 -j ACCEPT  # 代理（如用）
-A OUTPUT -p tcp -m multiport --dports 443 -j ACCEPT    # HTTPS 出口
-A OUTPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
-A OUTPUT -j REJECT
COMMIT
```

> firejail 的 netfilter 基于 IP/端口而非域名；按域名白名单仍需
> 代理（方案 A）或透明 DNS 劫持。生产建议：**方案 A 优先**。

---

## 3. 方案 C：共享网络 + 宿主防火墙兜底（最简，隔离最弱）

若无法断网/代理，保留宿主网络，用防火墙按 **agent-runner 服务账号**限制出口：

```bash
# iptables（按 uid 放行）：agent-runner 以 hermes-agent 账号运行
iptables -A OUTPUT -m owner --uid-owner hermes-agent -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -m owner --uid-owner hermes-agent -p tcp -d 198.18.0.0/16 -j ACCEPT  # 模型网关网段
iptables -A OUTPUT -m owner --uid-owner hermes-agent -j REJECT
```

## 4. 生产开启清单

```bash
# agent-runner 部署（裸机 systemd / Docker 环境变量）
SANDBOX_ENABLED=true
SANDBOX_CPU_SECONDS=120
SANDBOX_NPROC=256
SANDBOX_FSIZE_MB=256
SANDBOX_MEMORY_MB=0            # 强内存隔离交给 cgroups v2 / gVisor
SANDBOX_CMD="<方案 A 或 B 的 bwrap/firejail 命令>"
HTTPS_PROXY=http://proxy.internal:3128   # 方案 A 配套
```

K8s 额外：agent-runner 用 **gVisor RuntimeClass**（runsc）+ NetworkPolicy 限制出口。

## 5. 上线验证

```bash
# 1) 沙箱命令本身可解析（runner 启动日志无 sandbox 报错）
# 2) 发一条消息，确认 agent 正常回复（LLM 出口通）
# 3) 工具落地文件确认写在工作区内
ls ${WORKSPACE_ROOT}/<conv_id>/

# 4) 隔离性抽查：沙箱内无法访问宿主无关路径
#    让 agent 尝试读 /etc/shadow 或 ~/.ssh —— 应失败
# 5) 断网验证（方案 A）：agent 尝试 curl 外网非白名单域名 → 应超时失败
```

> 注意：`SANDBOX_MEMORY_MB` 保持 0（RLIMIT_AS 关闭），低值可能使
> python 解释器 fork 后 exec 失败；内存上限交给 cgroups/gVisor。
