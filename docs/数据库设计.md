# 数据库设计

PostgreSQL 16。模型在 `backend/app/db/models/`，迁移在 `backend/alembic/versions/`（0001–0090，线性串联）。
主键多为 UUID（`gen_random_uuid()`，pgcrypto）；时间戳 `created_at/updated_at`（带时区）。

---

## 1. ER 概览

```
users ──< team_members >── teams ──< projects ──< project_tasks
  │                          │
  │                          └──── policy (JSONB 内容权限矩阵)
  │
  ├──< conversations ──< messages ──< workspace_files
  │          │
  │          └──< scheduled_tasks（定时任务，绑定 profile）
  │
  ├──< agent_memory（user + profile 两级：notes/user_profile/soul）
  │          └──< memory_episodes（按会话摘要，profile 级）
  │
  ├──< agent_skills（技能：owner/team/profile 三级 + origin）
  │
  └── (external_id, source) ← 由 LDAP/SSO 关联

profiles（助手/Profile：人格、技能、知识、MCP、编排绑定，path=HERMES_HOME config）
agents (ACP 注册表，runner 探测写入)
knowledge_docs / knowledge_chunks（团队知识库 + 向量/关键词索引）
identity_providers ──< dept_team_mappings ┄┄(auto_join)┄┄> teams
system_settings (单行)        audit_log (自增, 只追加)
session_call_logs (自增, 每轮模型/工具调用一行, 会话日志用)
```

### agents（0002）— ACP 注册表（runner 探测 upsert）
`id(PK,text) · label · kind(acp_cli/builtin_mock) · available · official · version · color · icon · description · command(JSONB,spawn argv) · last_seen_at`

### teams / team_members / projects / project_tasks（0003）
- **teams**：`name · handle(unique) · tagline · color · plan · join_mode · policy(JSONB)`
- **team_members**：复合主键 `(team_id,user_id)`；`role(owner/admin/member/viewer) · status · joined_at`
- **projects**：`team_id · name · handle · color · icon · summary · progress · status(active/paused/archived) · sections(JSONB) · pinned_agents(JSONB) · visibility · deadline`
- **project_tasks**：`project_id · title · status(todo/doing/done) · owner_id→users · agent_id · order_idx`

### session_call_logs（0081）— 会话日志调用明细（只追加）
每轮对话的每次模型调用 / 工具调用一行，由 agent_runner 在 `_finalize`/`_fail` 落库；支撑后台「会话日志」的调用概览。

| 字段 | 说明 |
|---|---|
| kind | `model`（模型调用，token 从 usage/context_used 估算）或 `tool`（工具调用） |
| name / tool_kind | 工具标题 / ACP 工具类别 |
| status / duration_ms | 调用结果与耗时（工具精确、模型为事件间隔近似） |
| tokens_in / tokens_out | 模型调用 token 数 |
| started_at / ended_at | 起止时间 |

### profiles（0089 前已有，含绑定字段）— 助手 / Profile

每个 Profile 是独立的 AI 助手，运行在**独立 HERMES_HOME**（`~/.hermes/profiles/<handle>/`）；`path` 指向该 home 的 config.yaml（DB handle 带 `hermes-` 前缀 ↔ 目录名去前缀）。

| 字段 | 说明 |
|---|---|
| id, name, handle(unique), scope, color, icon, desc | 基础展示 |
| default_agent_id, default_model | 默认执行 agent / 模型 |
| team_id | 团队绑定（个人/团队助手） |
| system_prompt | 人格设定；变更时投影到 `{home}/SOUL.md` |
| path | HERMES_HOME config.yaml 路径 |
| skills | JSONB 技能 id 列表（历史兼容；新技能走 agent_skills.profile_id） |
| knowledge_ids / knowledge_folder_ids / knowledge_team_ids | 知识绑定 |
| mcp_server_names | MCP 服务器绑定 |
| is_moa / moa_target_profile_ids | MoA 编排 |
| is_chain / chain_target_profile_ids | 链式编排 |
| is_research / max_iterations | 调研模式 |
| staged_prompts / staged_enabled | 分阶段提示词 |

### agent_skills（0070s）— 技能（注入 system prompt 的条件技能）
| 字段 | 说明 |
|---|---|
| owner_id / team_id / profile_id | 归属（profile 绑定技能只进该 profile home） |
| name, description, content | 内容 |
| trigger_conditions | JSONB `{keywords:[…]}`；命中才注入 |
| enabled | 开关 |
| **origin**（0090） | `platform`（平台创建，DB 为源）/ `agent`（Direction B 从 hermes FS 入库；FS 目录消失自动 tombstone） |

同步机制：Direction A（DB→FS 写 `{home}/skills/{slug}/SKILL.md`，frontmatter 保留原始 name + `metadata.platform_skill_id`，slug 冲突加 `-{id8}` 后缀）；Direction B（FS→DB ingest，runner 启动 + 每日自动，按 id 匹配优先）。

### agent_memory / memory_episodes（0089）— 长期记忆
- **agent_memory**：每用户每 Profile 一行（`user_id + profile_id`），`profile_id NULL` 为全局层；读取 profile 专属优先、全局回退；写入 exact-scope（profile 写不碰全局行）。字段：`notes / user_profile / soul / last_consolidated_at`。唯一约束用两个部分唯一索引（Postgres NULL 不参与唯一比较）。
- **memory_episodes**：会话级摘要（`conversation_id + profile_id`），按需检索；consolidation 按 profile 分组生成。

### scheduled_tasks（0070s）— 定时任务
`name · cron(表达式) · prompt · agent_id · profile_id(执行助手) · conversation_id(专属会话) · enabled · last_run_at`

### knowledge_docs / knowledge_chunks（0070s–0083）
- **knowledge_docs**：团队知识库条目（folder 组织、向量索引状态、预览 PDF 键）
- **knowledge_chunks**：分块 + embedding（0082 加元数据、0083 加 tsvector 关键词列，混合检索）

### audit_log（0005）— 审计（只追加）
`id(BigInt Identity) · ts(索引) · actor_id · actor_name · action(索引) · target · ip · result(ok/fail/partial) · meta(JSONB)`

### system_settings（0005）— 单行租户设置
`id(=1) · data(JSONB) · updated_at`。data 结构见 [API 文档 §8](API文档.md)。

### identity_providers / dept_team_mappings（0006）
- **identity_providers**：`id(PK: ldap/wecom/saml/oidc/feishu) · label · enabled · config(JSONB)`，迁移预置 5 行。
- **dept_team_mappings**：`provider_id→identity_providers · match_basis(dn/attribute) · source_value · dept · default_role · auto_join_team_id`

## 3. JSONB 字段一览（为何用 JSONB）

| 表.字段 | 结构 | 原因 |
|---|---|---|
| messages.content | `{text}` 或 `{replies[],merged}` | 消息形态多样（单/圆桌/工具调用） |
| teams.policy | `{perm_id:{role_key:bool}}` | 权限矩阵随权限点演进 |
| system_settings.data | 品牌/模型网关嵌套 | 租户配置灵活 |
| agents.command | `["hermes","acp"]` | spawn argv |
| projects.sections / pinned_agents | 数组 | 轻量列表 |
| identity_providers.config | 连接参数 | 各提供商字段不同 |

> 迁移里写 JSONB 字面量务必 `CAST(:d AS jsonb)` + `json.dumps(...)`，避免双重编码（见 `0005_admin.py` 经验）。

## 4. 索引

- `users(email)` unique、`users(handle)` unique、`users(source,external_id)` unique
- `conversations(owner_id)`、`messages(conversation_id)`、`workspace_files(conversation_id)`
- `projects(team_id)`、`project_tasks(project_id)`、`dept_team_mappings(provider_id)`
- `audit_log(ts)`、`audit_log(action)`
- teams.handle unique

后续可按需加：会话标题全文检索（`pg_trgm`/`tsvector`）、知识库向量（`pgvector`）。
