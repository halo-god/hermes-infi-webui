### @real-agent 用例（CI 排除，本地全量）

依赖 ACP runner 流式回复真实 LLM 输出：

- `chat.spec.ts` — 新建会话并发送消息，助手流式回复
- `chat.spec.ts` — 多轮对话：追问后助手继续回复
- `group-chat.spec.ts` — 绑定多助手团队 → @圆桌 触发多 Agent 并行回复渲染

### 运行

```bash
# 本地全量（含 @real-agent，需 runner 在线）
npx playwright test

# CI 子集（排除 @real-agent）
npx playwright test --grep-invert @real-agent

# 环境变量（默认即本地栈，CI 覆盖）
E2E_BASE_URL=http://localhost:5173 E2E_API_URL=http://localhost:8001
```

E2E 前置自动清理（global-setup → `e2e/cleanup.ts`）：删除上一轮残留的 `E2E ` 前缀团队与定时任务，避免 `.first()` 命中过期数据。

## CI 全链路（.github/workflows/ci.yml）

```
security    pip-audit
backend     ruff → alembic → seed → pytest（--cov-fail-under=60）→ artifact
frontend    npm audit → type-check → vitest（coverage 门槛）→ build → artifact
e2e         postgres+redis → alembic → seed → uvicorn :8001 → vite build+preview :5173
            → playwright（--grep-invert @real-agent）→ artifact
```

## 测试可靠性约定

- **登录限流**：CI / 本地 E2E 均设 `LOGIN_RATE_LIMIT_PER_MIN=100000`（测试高频登录）；生产保持默认 10/min
- **测试专用 Redis**：后端测试强制 `127.0.0.1:6380`（conftest 校验，禁止打生产实例）
- **E2E 单 worker**：用例共享真实后端，禁止并行竞态
- **覆盖率门槛**：单文件本地跑不会误触（fail-under 仅在 CI 命令行传入）
